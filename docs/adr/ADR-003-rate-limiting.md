# ADR-003: Rate Limiting и защита от злоупотреблений

**Дата:** 2025-01-22
**Статус:** Accepted

## Context

Приложение Learning Flashcards подвержено различным типам атак и злоупотреблений:
- Брутфорс атаки на эндпоинты аутентификации
- DoS атаки через перегрузку API
- Злоупотребление ресурсами (создание множества колод/карточек)
- Спам через API эндпоинты

**Проблемы:**
- Отсутствие защиты от брутфорса
- Нет ограничений на частоту запросов
- Возможность создания неограниченного количества ресурсов
- Отсутствие защиты от DoS атак

## Decision

Реализовать многоуровневую систему rate limiting:

1. **Глобальный rate limit** - 120 запросов в минуту на пользователя
2. **Защита логина** - 10 неуспешных попыток в минуту на IP
3. **Защита создания ресурсов** - лимиты на создание колод/карточек
4. **Адаптивные лимиты** - снижение лимитов при подозрительной активности
5. **Graceful degradation** - постепенное ужесточение при превышении

**Параметры:**
- Глобальный лимит: 120 req/min на пользователя
- Логин лимит: 10 неуспешных/мин на IP
- Создание колод: 5/час на пользователя
- Создание карточек: 100/час на пользователя
- Время блокировки: экспоненциальное увеличение (1min, 5min, 15min)

## Alternatives

### Альтернатива 1: Только глобальный rate limit
**Плюсы:** Простая реализация
**Минусы:** Не защищает от целевых атак

### Альтернатива 2: Жесткие лимиты для всех эндпоинтов
**Плюсы:** Максимальная защита
**Минусы:** Может ограничить легитимных пользователей

### Альтернатива 3: Только защита критических эндпоинтов
**Плюсы:** Минимальное влияние на UX
**Минусы:** Недостаточная защита

## Consequences

**Плюсы:**
- Защита от брутфорса и DoS атак
- Защита ресурсов от злоупотреблений
- Улучшенная стабильность системы
- Соответствие security best practices

**Минусы:**
- Дополнительная сложность в реализации
- Потенциальное влияние на UX при превышении лимитов
- Необходимость настройки и мониторинга

**Влияние на производительность:**
- Минимальное - проверка лимитов быстрая
- Возможное снижение пропускной способности при активном rate limiting

## Security Impact

**Закрываемые риски:**
- R1 (Брутфорс логина) - защита эндпоинта логина
- R5 (Перегрузка API) - глобальные лимиты
- F5 (DoS атаки) - защита от перегрузки

**Новые меры безопасности:**
- Защита от брутфорса через лимиты на логин
- Защита ресурсов от злоупотреблений
- Адаптивные лимиты для подозрительной активности
- Мониторинг и алертинг при превышении лимитов

## Rollout Plan

1. **Этап 1:** Реализация базового rate limiting middleware
2. **Этап 2:** Добавление защиты критических эндпоинтов
3. **Этап 3:** Интеграция с системой мониторинга
4. **Этап 4:** Настройка алертов и мониторинга

**Definition of Done:**
- [ ] Реализован rate limiting middleware
- [ ] Добавлена защита всех критических эндпоинтов
- [ ] Настроен мониторинг и алертинг
